# Редактирование контента через Keystatic

## Вход в админку

- На приватном editor host: откройте локальный адрес Keystatic после запуска
  editor environment; публичный VPS не предоставляет `/keystatic`.
- Публичный VPS обслуживает только статический сайт через Nginx и не запускает
  Node/SSR, Keystatic или базу данных.

## Как это устроено

Keystatic — не отдельная база: он редактирует те же файлы `src/content/`, что видит и агент, и разработчик. Каждое сохранение — изменение файла (локальный режим) или коммит в GitHub (github-режим). Историю правок смотрите в `git log`.

## Посты

1. Collections → **Blog Posts** → *Create*.
2. Заполните Title (из него создастся slug), Description (это meta description — важно для SEO), дату, теги.
3. Пишите текст в редакторе — форматирование, ссылки, изображения поддержаны.
4. Пост создаётся черновиком (**Draft** включён). На сайте не виден.
5. Публикация: снимите галочку Draft и сохраните.

## Настройки сайта

Singletons → **Site Settings**: имя сайта, слоган.

## Два режима хранения

| Режим | Где работает | Как сохраняет |
| :--- | :--- | :--- |
| `local` | локальная разработка без публикации | пишет файлы в рабочую копию |
| `github` | приватный editor host | коммитит в GitHub через GitHub App |

Для редактирования используйте приватный editor host и переключите
`keystatic.config.ts` на `github` — инструкция в `hosting.md` и
`hosting/vercel/README.md`. Публикация выполняется отдельной проверенной
статической сборкой; публичный VPS не является editor host.

## Совместная работа с агентом

Вы правите через админку, агент — напрямую файлами. Конфликтов нет, пока оба коммитят в git и не редактируют один файл одновременно. Крупный контент (циклы статей, SEO-оптимизация) удобнее заказывать агенту; точечные правки — руками через Keystatic.
